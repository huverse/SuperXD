# playground 游乐场

定位：服务页里的小游戏（娱乐，不算工具，所以不进百宝箱）。设备级，只依赖 domain 与 theme，不依赖教务相关的任何层；自由模式免教务登录，本机成绩切换账号保留。益智板块的游戏在 puzzle 目录，登记在 puzzle/CLAUDE.md。

- [人工决策-2026-11-12 21:00:20] 用户提出游乐场（自由模式与挑战模式）、积分与灰度，并要求架构按长期设计、分类按大厂做法。用户选定的全部选项写在 playground_catalog.dart 与下面的「长期路线」，代码处的注释只写结论。

# 架构

- 三级登记：板块（益智，以后加休闲、棋牌等）→ 子类（逻辑推理、数字计算、格子谜题、移动与规划、记忆与反应、物理）→ 游戏，只在 playground_catalog.dart 一处登记，id 发出后不改（本机记录、以后的题库、挑战与积分都按 id 认）。实装一个登记一个，不放占位卡。
- 每个游戏是规则加页面两部分：
  - 规则是纯 Dart（不引 Flutter），实现 puzzle_rules.dart 的 PuzzleRules：按种子与档位出题并给参考解、按规则判定答案（不和参考解逐项比）、难度分 1–10、题面与答案编解码（解码是外部输入边界）。出题只用 PuzzleRandom（32 位运算，换语言能逐位复现）。
  - 页面用 play_frame.dart 的 PlaySession 管档位、计时与记成绩，用 PlayFrame 搭顶栏、状态行与底部操作，棋盘自己画。
- 挑战模式（人工决策见 challenge/challenge_rules.dart 文件头）：服务器（server/src/modules/challenge）按配置下发每周的 N 连环，出题用题库（tool/challenge_bank.dart 用同一份规则、保密种子离线生成）、逐关核对（TS 判定从规则逐个移植，与 Dart 共用 server/test/vectors/challenge_judge_v1.json）、计时（不暂停）与结算积分；关卡之间用碎片连起来（11-14 夜取代钥匙填空）：过关给一次从解里读出的碎片，收碎片的关先开门（门上的数是几块碎片之和或之积），门上的数改写这一关的一处条件或目标，全部过了输终章（全部碎片之和），快得不正常追加加试题。客户端只按服务器给的关卡图通用地画，模板、计分与题库改了不用发版；新游戏要发版。同一个对局页给了 PlayChallenge 就是挑战里的一关：题面与档位固定、不换题、不记本机成绩，判对错与完成都交服务器。拼手速与物理模拟的游戏（challengeable 为假）只进自由模式。
- 挑战与积分经组合根注入的 domain 端口 ChallengeHub（application/challenges.dart 实现）使用，游乐场不依赖应用账号与中转；去登录应用账号的页面也由组合根以回调给。
- 11-16 起游乐场一直能进（娱乐与积分的开关并进应用账号页的联网偏好，人工决策见 domain/leisure.dart 与 domain/network_policy.dart）：仅本机时路由不给挑战分段，组合根停掉解锁与等级加权；游乐场自己不知道联网偏好。

# 关键规则

- 出题只用 PuzzleRandom，不用 dart:math 的 Random（挑战题库与服务器要逐位复现）；规则文件不引 Flutter（tool 下的题库工具要能直接跑）。
- 给能进挑战的游戏换题面写法（puzzleVersion 加一）：先 dart run tool/challenge_vectors.dart --freeze <游戏>（把旧版本的向量搬进 server/test/vectors/challenge_judge_frozen.json），再改规则与版本号，服务端 judges.ts 给这个游戏加上新版本的判定、旧版本的留着（已发布的旧客户端还报旧版本），最后重跑向量工具；合并部署后由 challenge.yml 生成新版本题库，旧版本题库文件留在中转。服务端 challenge.e2e.test.ts 用当前向量入门档的题当题库、按第 1 版（旧文件名、只报游戏名）放，换了版本的游戏要加进 legacy 改从冻结的「游戏@1」取（11-17 冰面与汉诺塔升版本时 CI 踩过）。几个游戏同时换版本合并时，冻结文件取各家的并集，当前向量用本工具重生成。
- 判定按规则，不和参考解逐项比；每道题出之前用求解器确认可解，需要唯一解的游戏（如数织）确认唯一。
- 本机记录有上限：游戏数乘五档的最好成绩、最近玩过 playgroundRecentLimit 个，不随玩的次数增长；只有成绩，不排除出云备份。
- 对局页：自由模式按登记项的 clock 开始计时（题一出现、第一下或对局页自己的「开始」），同一道题从头来不清表；违规的操作轻震、退回，不算步数；解开后先放完收尾动画再弹结果；换档换题时页面自己清棋盘再调 session。
- 防乱点刷成绩（11-17 用户要求，各游戏的作弊机器人摸底与结论见下面一条）：有即时对错、错了不罚的就罚时（舒尔特点错 1 秒，骑士与无赖、逻辑网格判错与天平称球指认错罚 wrongPenalty），亮出答案的不记成绩（扫雷踩雷），快得不正常的不记成绩（换一道题接着蒙碰出的一两秒），挑战里试错一律交服务器计错交、不在本机白给对错。
- 作弊机器人摸底（11-17，build/superxd_verify 下的手动脚本，不进仓库）：汉诺塔、点灯、推箱子、过河、24 点、八皇后（简单起）、数织、数回、记忆闪光、密码破译、画线入杯乱点或穷举都比预计用时慢得多，不用改；冰面入门（6×6 只有岩石）乱滑常能碰到终点、八皇后入门（5×5）乱放冲突就拿掉也很快，是题太小，没改题型；换一道题接着蒙碰出的极快成绩由「快得不正常不记成绩」挡掉。
- 棋盘上的文字（提示数字等）用应用字体 14 号起，跟着字号缩放；格子太小时给双指缩放，不把字缩到 14 以下。
- 不写「挑战」二字到自由模式的按钮上（那是挑战模式的名字）。
- 物理模拟用 forge2d（Box2D v3 的 Dart 绑定，C 源码由构建钩子按目标平台编译、经 FFI 调用，不依赖 Flutter，规则文件里也能跑；本机跑测试要有 clang 或 gcc，Box2D 的 MIT 声明写在 assets/third_party_notices.txt）；浮点模拟只保证同一台设备上判定稳定，所以用它的游戏 challengeable 为假。
