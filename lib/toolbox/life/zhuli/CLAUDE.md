# toolbox/life/zhuli 住理生活

定位：百宝箱「生活」的第一个子模块（id life.zhuli，路由 /toolbox/life/zhuli，11-27 起不经功能开关、一直显示，人工决策见 domain/feature_flags.dart），对接住理生活（com.whxinna.userplatform 3.12.8）的校园水控：洗浴开关、充值与买券、余额与优惠券、订单。账号是住理生活账号，与教务、学习通都无关；协议按资料 ~/Projects/SelfProjects/API/shenghuo/zhuli（集成文档、逆向报告、样本，仓库外）用 Dart 重写，11-22 用两个授权测试账号实测过。分轮做：第一轮登录、余额与券、订单只读；第二轮洗浴：四个入口、开水关水（云端与蓝牙，11-22 抽样 50 台里 46 台只有蓝牙，蓝牙开阀从第四轮提前，11-22 真机两路都开关过水）、接回没结束的单、快捷入口「扫码洗浴」；第三轮充值与买券（支付宝 SDK，插件 tobias，11-22 真机 0.01 元付通）；第四轮两用设备可选走蓝牙、列设备处写设备号与有哪几路、首页重排；进行中通知与报修 11-23 用户取消、不再开发。框架契约（子模块、服务、清除数据）见上两级 lib/toolbox/CLAUDE.md。

- [人工决策] 在 zhuli_service.dart 文件头（11-22 用户两轮选项：灰度、风险立场与不碰的后门和越权点、支付、设备列表、充值金额、余额与券的显示、增项、不做强制结束与消费投诉；登录方式与改选短信找回密码；11-23 取消进行中通知与报修并全量）。

# 文件职责

- zhuli_protocol.dart：请求协议（纯计算）：平台端地址与写死的签名密钥、上报的 App 版本；签名 zhuliSign（去空值、按键排序、值按 JS 的 JSON.stringify、去引号与空格、MD5 转大写，向量来自被真实服务端接受的实现）、对象参数换成 base64_<名>（zhuliBase64，同原 App 的 base64 再换 - 与 _）、带时刻与 32 位随机串的查询参数 zhuliQuery、回复 data 的解码 zhuliDecodeData（照原 App：先 base64、解开再试 JSON，不是 JSON 就是字本身，蓝牙命令帧就是这种；不是 base64 原样）。
- zhuli_http.dart：请求封装 ZhuliHttp（经共用内核 CampusHttp，模块 zhuli）：只发 GET，整次 15 秒、响应上限 1MB，不自动重试；result 为假时 zhuliRejection 按 err_msg 与 msg 归类（login_timeout 与 api_sign_error 是会话过期（后者是在官方 App 或别处登录换掉了签名密钥，11-24 真机诊断包），三种图形验证码文案要验证码，中文文案原样给人看，错误码另放在 ZhuliException.code）；日志只记路径与英文错误码，不记查询串（有手机号、密码、签名）与回复。
- zhuli_models.dart：失败分类 ZhuliFailure 与 ZhuliException；外部输入边界 decode*（逐项核对类型）：登录会话 ZhuliSession（业务地址只认 https 的 whxinna.com 主机、session_secret 盖过 appsecret，只在内存）、账户 ZhuliProfile（余额以用户详情为准，登录回复里的不可信；计费规则 ZhuliChargeRule 按设备类型与设备分组对上）、配置 ZhuliConfig（消费订单可查天数、洗浴开关、余额门槛、供水时段硬拦、充值与支付宝开关、两用设备选路的 network_selection）、设备 ZhuliDevice（开水默认走哪一路 channelWith 照原 App 的 oi()：change_network 先于优先通道、不止一个通道时看学校设定 network_selection；这一次走哪一路 via 与 using；两用设备 dual、给人看的 modeLabel 与和房间不同才写的设备名 distinctName；供水时段按北京时间钟点）、楼栋楼层房间 ZhuliPlace、下单回复、蓝牙握手、最近一单、券 ZhuliCoupon 与三栏 ZhuliCouponTab（回复里的 status、is_blance 恒为空，只能靠入参过滤）、券的抵扣记录、充值订单、消费订单与详情 ZhuliBill；金额一律按分的整数（生活根目录的 lifeCents 按十进制文本四舍五入到分、不经浮点运算，lifeYuan 写回元，和胖乖共用）；状态、消费类型、支付方式的中文。
- zhuli_client.dart：接口 ZhuliClient：登录（手机号加 6 位数字密码，只报系统类型与本工具的随机设备串、机型报 SuperXD）、图形验证码（SVG）、找回密码（短信验证码与重设）、用户详情、配置、我的券（页从 0 起）、券的月度抵扣记录（page_index 0 是整月）、充值订单（页从 1 起、不满 20 条到底）与详情、消费订单（起止必填、一次最多 20 条，用上一页最后一条的时刻翻页）与详情；洗浴：楼栋、楼层、房间与房间设备（页从 1 起）、按设备号或蓝牙地址找设备、待支付的单、最近一单（从没用过水的账号回 error_record_not_exist，算没有最近一单）、云端开水（先唤醒、不发金额）与关水、蓝牙的六个命令帧接口（帧只在服务端与设备之间搬运，_frame 只认 20 字节的十六进制）。住理的时间是不带时区的北京时间（对方协议的写法，不是业务时区）：zhuliMoment 换成 UTC 交给界面、zhuliClock 把时刻写回去，只在这里换算。

# 关键规则

- 不用资料里靠测试手机号触发的 mp.whxinna.com 调试转发；staff_id 一律空（只查自己的）；资料第 14 节列的越权点（URL 透传的 staff_id、伪造结果页这类）一个都不碰。
- 网络：住理的两个域名在阿里云高防后面，国内网络直连通、境外出口超时（11-22 实测）；开发机上的探针要绕开代理软件走国内出口。
- 凭据：密码登录成功后才进系统安全存储，退出账号或清除数据即删；会话（签名密钥与身份码）只在内存，约 20–40 分钟过期，过期按记着的密码重登。余额、券与订单即查即用、不落盘。
- 金额：只显示服务端给的数，客户端不推算抵扣（住理按券的 use_order 自己扣，客户端没法选券）；金额按分的整数处理。充值金额客户端限死（住理只拒负数，0 与 0.001 都能下单）；买券不带金额（住理按商品定价）；付款只走支付宝（微信按应用签名认 AppID 做不了），只认支付宝 APP 支付串；支付串不进日志；到账只认住理（支付宝回调写库，客户端只查）。iOS 的支付宝 SDK 经 tobias 的 SPM 依赖 JarvanMo/AliPaySDK-SPM（插件作者转包的二进制，11-23 核过里面是支付宝构建机路径与 15.8.42），两份 Package.resolved 钉死提交号；安卓的是 Maven Central 上支付宝发的 com.alipay.sdk:alipaysdk-android。升 tobias 时照 CONTRIBUTING.md「供应链」从 CI 取锁文件核对。
- 第三方来源：首次登录前单独征得同意（consentVersion），说明有实质变化就加一档；同意记录按 life.zhuli 记，清除数据时框架撤销。隐私政策第十节、用户协议第五节「百宝箱」、附录一（SDK 第 4 项支付宝 SDK、服务第 8 项）、附录二（Wi-Fi 状态，随支付宝 SDK 带入）与附录三本机第 7 项写明，改采集或去向要同步。
- 保留：账号最多 10 个；本机只存设备列表（每个账号最近 6 台、常用 20 台），不存余额、券与订单。
