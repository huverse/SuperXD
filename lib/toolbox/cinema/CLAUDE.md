# toolbox/cinema 电影院

定位：百宝箱里的在线影视（灰度测试，功能开关 toolbox.cinema 开着才出现）：多源搜索、选集、播放与云解析（解析先不开放，在开关 toolbox.cinema.parse 后面，默认关，规则包第 4 版起没有解析源，人工决策见 domain/feature_flags.dart），规则写法借鉴 Kazumi（GPL-3.0，出处见 assets/third_party_notices.txt）。搜索、选集、解析与取流在手机上直连第三方片源（国内连不上的源的搜索与选集经开发者部署在 Cloudflare 上的境外转发，Worker 在 server/edge/cinema_forward.ts，人工决策见 cinema_rule.dart 的 CinemaRule.forward），自建中转只发签名的片源规则包，另替片名目录型的源（不给按片名搜的，如 wsy）查片名对应的编号（服务端 src/modules/cinema_catalog）；规则包不进公开仓库，维护者本机签名后上传（tool/cinema_rules.dart、tool/cinema_publish.sh）。四项用户选择与服务器负担的取舍见 cinema_service.dart 文件头的人工决策。

# 文件职责

- cinema_rule.dart：规则包的外部输入边界 decodeCinemaPackage（验签后的载荷字节 → CinemaPackage）：规则 CinemaRule 是 Kazumi 的 API 模式（请求模板 CinemaRequest、搜索 CinemaSearchConfig（11-21 起可写分类路径 categoryPath，规则包第 6 版写的是 type_name，旧版本忽略）、选集 CinemaChapterConfig 的 delimited 与 nested 两种）加电影院的扩展（规则 id、海报年份备注路径；11-20 起搜索配置可带 chapters：搜索回复每一条自带的剧集，路径相对每条记录、格式同选集，旧版本忽略）；云解析 CinemaParser（回复的业务码按字符串比，地址可按 CinemaCipher 的 AES-128-CBC 解密）。11-20 起片名目录型的源放在顶层 catalogRules（CinemaCatalogConfig：给中转抓片名用的 update 请求，带 @hours、@page，手机只核对写法；搜索请求用 @ids），解出来接在普通源后面、同一个列表；1.0.0-alpha.34 不认这个字段、照旧只用普通源。11-21 起规则包顶层可写境外转发地址 forward（只认 https，不带端口与查询串），规则写 forward: true 的搜索与选集经它（只支持 GET），同意的主体 host 带上转发主机（改走转发要重新同意），旧版本忽略这两个字段、照旧直连。JSONPath 只认 Kazumi 限定的写法（validateCinemaJsonPath）；上限 cinemaRuleLimit（两种合计）、cinemaParserLimit、cinemaPackageMaxBytes，不合格整包不用。
- cinema_rule_engine.dart：规则引擎（移植 Kazumi 的 ApiRuleStrategy，纯计算）：prepareCinemaRequest 填 @变量（url 里按 URL 编码、表单按 form 编码），parseCinemaSearch（取出分类 category；写了 search.chapters 的每条按自己的记录解出剧集，不套详情的 $.list[0]；一条没取到时，回复里有列表容器（空数组或 null）是搜不到，连容器都没有（HTTP 200 的「服务器繁忙」）或是别的类型报错、算这个源失败；上游的 msg 不进日志，可能带着片名）、parseCinemaChapters 与共用的 parseCinemaRoads（只留能直接播的媒体地址，空线路整条不要，相对地址按请求地址补全，集名缺省按序号起名），parseCinemaParserReply；回复不看 Content-Type 直接按 JSON 解。
- cinema_models.dart：搜到的一条 CinemaHit（category 是分类，roads 是搜索自带的剧集）、各片源最近的播放结果 CinemaSourceStat 与片源排序 rankCinemaSources、标注 cinemaSourceStatLabel、聚合后的一部片 CinemaTitle（各源的海报按先后留着，取不到换下一家；片源只经 addSource 加、加了在 changes 上通知（纯 Dart 的同步流，模型不依赖 Flutter），打开着的选集页与播放页用 appendCinemaSources 接在菜单末尾；category 是第一个回来的源给的分类）、一条片源 CinemaSourceRef（carried 是搜索自带的剧集，跟着这一次的搜索结果走、不进选集缓存）、选集 CinemaRoad 与 CinemaEpisode、失败 CinemaFailure（页面只写源名 name，原因 message 只进日志；paused 是连续失败暂停着的）、边搜边给的快照 CinemaSearchResult（pending 是还没回来的源数）、看过的 CinemaHistory（finished：剩下不到片长 5% 或 3 分钟，取更短的，[人工决策] 在 getter 上）；换源找同一集 cinemaMatchEpisode（原名、集号 cinemaEpisodeNumber、两边都只有一集）；换源后片长对不上 cinemaCutDiffers（[人工决策] 在函数上）；片名折叠 cinemaFold（去空白、全角折半角、小写，没有 NFKC 时只折这两类）与聚合键 cinemaTitleKey（折叠加四位年份，分类带预告、解说、花絮的另加后缀单独成条，[人工决策] 在函数上）、媒体地址判定 cinemaMediaUrl。
- cinema_http.dart：对外请求封装（经共用内核 CampusHttp，模块 cinema）：默认桌面浏览器 UA、不带 Referer（规则写了才带），接口请求另带 accept 与 accept-language（cinemaApiHeaders，规则写了同名头以规则为准）；接口 15 秒、2MB，云解析 30 秒，清单 25 秒、8MB；本机代理取清单时自己跟跳转（最多 5 跳，各跳共用一个总时限，拿最终地址补相对路径），可取消；不自动重试。text 带 forward 时发给境外转发（原地址在查询串 u，请求头照带），转发自己出的错（回复头 x-forward-error）按直连时的原因报。CinemaShared 是几处共用的一次请求：每处可以各自不等了，都不等了才中断。
- cinema_playlist.dart：m3u8 改写（纯计算）：子清单与 AES 密钥回到本机代理，分片与初始化段换成绝对地址交给播放器直连，其余一行不动、一个分片不删（11-21 起不再去广告，规则里的 adBlocker 不读，[人工决策] 在文件头）；腾讯 CDN 域名前置的还原 cinemaUnwrapHost；打开前预取用的各码率地址 cinemaVariants 与第一把密钥 cinemaFirstKey。
- cinema_proxy.dart：手机上的本机代理 CinemaProxy：只监听 127.0.0.1 随机端口，路径带随机令牌；p 取清单并改写，k 取密钥（16 字节，按地址记最多 64 把）；每路播放换掉时 release，还在等的请求随之不等了；分片清单第一个分片的路径首段像域名时原地址与替代地址同时探（原地址优先，共用 probeBudget），结论按主机加请求头记 probeKnownFor（没定论的 probeUnsureFor），主清单不探；点播与主清单缓存 playlistLifetime（直播不缓存），warm 预取（可取消）：主清单再取各码率子清单（最多 warmVariants 个）、第一把密钥与探测，打开前先等它备好再交给播放器（mpv 5 秒读不到就放弃，[人工决策] 在文件头），「重新载入」的预取（fresh）不用缓存、重新探测；播放器等不及先断开的记 client_gone；缓存与探测结论只让当前有效的那次写；开发者模式下逐份记播放器来取的清单预取过没有、用没用上缓存、跳没跳转与密钥用时（预取命中率，不记地址）。视频字节不经代理也不经服务器。
- cinema_cloud_parse.dart：云解析 CinemaCloudParse：输入本身是媒体直链时不发给任何人；结果只在内存留 3 分钟、最多 32 条，「重新解析」跳过缓存；decryptCinemaUrl 是 AES-128-CBC 加 PKCS7（key、iv 是原文字节）。上游对不支持的地址也回成功并给提示影片，照样显示标题并播放（沿用懒猫交接里用户的决定，[人工决策] 在文件内）。
- cinema_store.dart：本机库 cinema.db（单实例、回滚遗留事务，第 2 版起有播放记录，第 4 版起有设置表 preference，现在只记播放内核）：上次验签通过的规则包、同意记录（按规则 id 与接口主机）、看过的记录（最多 cinemaHistoryLimit 条、cinemaHistoryLifetime 没再看的删掉）、第 3 版起看过的片在各源的编号 title_source（每部最多 cinemaTitleSourceLimit 个，跟着看过的记录删）、各片源最近播成与没播成的时刻与首帧用时 source_stat（每个源一行，cinemaSourceStatLifetime 没再播的删掉）。
- cinema_catalog.dart：片名目录型的源 CinemaCatalog（[人工决策] 在文件头）：片名 POST 给中转（不进地址）拿回最多 catalogHitLimit 个编号（decodeCatalogIds 是外部输入边界），再把编号一次发给这个源取详情，按中转给的先后排；没配中转时报错、进暂不可用。手机上不下载、不存目录。
- cinema_service.dart：服务 CinemaService：规则包（本机缓存，两次拉取至少隔一小时，版本只升不降，minClient 高于本机构建号的不换，拉不到照旧用本机的，失败后 retryGap 内不再拉；同意与搜索用 usable：本机有就直接用、不等后台刷新）、同意、多源并行搜索（一次全发，最多 searchConcurrency 路、每源 20 条，同一个源同一个词正在搜就一起等，最近一分钟的结果直接用（searchCacheLifetime，只记成功的，fresh 不用，[人工决策] 在常量上），边搜边给快照，按片名加年份聚合、按第一次出现的先后排只往后加，失败的进 failures，开发者模式下逐源记排队、用时、结果分类（search_source），真去请求的记网络与解析用时、字节（search_fetch），整轮记首条与全部结束，都不记片名；片名目录型的源经 CinemaCatalog 问中转）、连续失败暂停（pauseAfter 次后暂停 pauseFor（11-21 起 2 分钟），只在内存，resume 立即恢复，[人工决策] 在常量上）、选集（内存缓存 chaptersLimit 部、chaptersLifetime，键带规则包版本；搜索自带的剧集挂在片源上（carried，一次搜索最多 carriedEpisodeLimit 集），chapters 先看缓存再看 carried；同一部片同时只发一次，各处可单独取消；fresh 跳过缓存，旧请求晚回来不覆盖新的）、交给播放器的地址（m3u8 先等本机代理预取备好再经它交出，用完 release；CinemaPlayable.playlist 标明是 HLS，系统播放器要明说格式）、本机记下的播放内核 enginePreference 与 chooseEngine、预取 warm、播放记录 sourceStats 与 recordPlayback、片源显示名 cinemaSourceLabel；播放页的「找其他片源」findMoreSources（点了才按片名走一次搜索，跳过这部片已有的源与 recentFailure 内刚失败的，同聚合键的源接进这部片，[人工决策] 在方法上）；清除数据删整个 cinema 目录。四项用户选择与服务器负担的取舍在文件头 [人工决策]。
- cinema_page.dart：首页（本机有规则包时先显示、后台更新，时长券不挡页面）：找片（看过的是横向海报条、⋯ 里删除先确认；搜索结果（边搜边显示，写还在搜几个源，搜索中输入框照常可改、改了词重新搜）、暂不可用的源只写名字，有暂停着的给「重试暂停的源」；清空搜索框回到看过的并中断没搜完的；[人工决策] 在 _onQuery 与 _historySlivers）与解析两段（解析开关经运行时的 features 问，关着时只有找片、不显示切换，开关变了立即刷新）；搜索结果写年份、分类与备注；结果显示着时再按搜索同一个词是重新搜（fresh）；搜索结果点开一律进选集页（不做单集电影直接播，[人工决策] 在 _openTitle）；看过的点开直接进播放页，片源菜单里带上本机记下的别的源（[人工决策] 在 _resume），看完了的从下一集开头，记下的都不行在播放页找其他片源；第一次搜、第一次用云解析前征得同意（片名目录型的源写明片名经开发者服务器查找、经境外转发的源写明经开发者的境外转发，cinemaConsentName）；中转写了时长券而当前账号没换时显示兑换卡（人工决策见 domain/pass.dart）。
- cinema_detail_page.dart：选集页：大标题下写年份、分类、备注与几个源；顶栏片名在正文大标题滚出去后才出现（[人工决策] 在 _onScroll）；选片源（按播放记录排一次、标注，之后来的源接在末尾）、选线路、点一集播放（CinemaEpisodeGrid），上次看到的那集标成选中、可接着看（看完了的变成看下一集或从头看）；取到选集后预取接着看那一集，播放时把选集交给播放页；换源、离开时取消这一处的等待。
- cinema_player_page.dart：播放页（播放内核经 CinemaEngine，createCinemaEngine 按本机记下的选择建；「播放内核」菜单写正在用的、换了记在本机并在当前位置用新内核重开（倍速音量带过去）；系统播放器首帧前打不开（open 抛错或首帧前报错）时这一页退回 mpv 一次，日志记 engine_fallback；首帧按 cinemaFirstFrame：从中途开的要等时钟越过起点或打开中见过的最早位置；打开中收到跳转改成在目标位置重开）：竖屏上面画面（高度跟片子的真实比例，竖片最多占屏高 cinemaPortraitMaxHeight）下面选集（CinemaEpisodeGrid；线路分段只换看哪条线路的集数，点了某一集才换过去播）与换源（cinemaMatchEpisode 找同一集；之后来的源接在菜单末尾）、找其他片源（按钮原地转圈）、重新载入（云解析的重新解析）、15 秒还在缓冲提示换源；选集页给的选集直接用（重新载入才强制重取）；每次打开记一次播放结果（首帧与出错只认播放器当前项是这次交出去的媒体，旧视频晚到的事件不算；出错即结束这次打开、放开换源，换源没成时还原原来的错误）、快播完预取下一集（离开时取消）、换掉时交回本机代理并取消旧请求；「重新载入」连清单缓存与探测一起重来；记看到哪按 CinemaSaveSchedule（每 10 秒；暂停、跳转后 1 秒合并着记；切到后台、换集换源、离开时立即记；进度还没动、出错时不记），记的时候片源多了就把这部片的各个源也记下；换源后片长对不上提示可能是别的剪辑（cinemaCutDiffers）；开发者模式下记每次打开（第几次、源、起播位置、本机代理的 stream）、首帧、卡住缓冲多久、每次跳转的目标、发出时在不在缓存里、真正恢复用了多久与落点（CinemaPlaybackTruth）；打开中或卡住缓冲时让小网络图先等（ToolboxImageGate）、不预取下一集；播放器报错的原话进日志前去掉网址（cinemaLogSafe）；全屏在同一页里切（画面与控件经 GlobalKey 挪过去），横片转真横屏、退出回竖屏（[人工决策] 在清单的 MainActivity 与 ios/Runner/Info.plist）。
- cinema_engine.dart：播放内核（[人工决策] 在文件头，11-21 真机对照后用户选定）：接口 CinemaEngine（字段名照 media_kit，播放页与控件只换类型），mpv 实现 CinemaMpvEngine（media_kit 加 CinemaPlaybackTruth）与系统播放器 CinemaSystemEngine（video_player：安卓 ExoPlayer、iOS AVPlayer；每个媒体一个控制器，回看缓冲 backBuffer，进度每 tick 问一次，请求头经 cinemaSystemHeaders 改成标准写法）；安卓默认系统播放器、iOS 默认 mpv（cinemaDefaultEngine、cinemaEngineOf），打不开抛 CinemaEngineException；测试用 debugCinemaEngineFactory 换掉真的内核。
- cinema_playback_truth.dart：播放器的真实状态 CinemaPlaybackTruth（11-21 Codex 总交接第 12.5 节与复核）：直接问 libmpv。跳转两个指标：原生恢复（seeking 变回 no 且此刻位置在目标 seekTolerance 内，挡掉上一次晚到的 no；不要求先看到 yes，命中缓存时通知会合并）与目标处走起来（恢复后时钟越过目标 playingLead，mpv 的时钟跟着输出的画面走，不是屏幕截帧）；begin 发出时记目标在不在缓存里（true、false、读不到为 null），连着跳只认最后一次，reset 在换媒体时放弃还在等的。缓存段三种：真实的几段、明确没有（空列表）、读不到（null）（cinemaSeekableRanges，外部输入边界）。首帧时 decoder 记硬解与版本。测试替身问不到，经 notify 喂值。
- cinema_player_controls.dart：播放器控件与手势 CinemaPlayerControls（[人工决策] 在文件头，借鉴 Kazumi 与主流平台）：单击显隐、双击暂停继续、长按倍速、左右滑调进度（松手才跳）、左半边上下滑亮度（只改本应用窗口，离开恢复）、右半边音量；上栏倍速与画面比例 CinemaFit，播放暂停在下栏与画面中间各一颗（共用 _playButton，图标都写点了会怎样；中间那颗只在控件显示着、中间没有加载动画、报错、拖动或调节提示、连播倒数与面板时出现），下栏播放、下一集、带缓冲段的进度（已缓冲按真实的几段画，明确没有不画，读不到时只画当前位置到缓存末端，cinemaCachedSpans；片长还不知道时两边写 --:--、不画圆点）（画与点按共用左右缩进 _progressInset）、所有跳转发出时（命令交给播放器之前）经 onSeek 告诉播放页、选集（全屏）、全屏；全屏可锁定；从头播放、播完倒数 cinemaAutoNext 连播下一集（没有跳过片头，11-21 用户要求删掉，[人工决策] 在文件头）。不用 media_kit 自带的控件（它的转圈会叠在我们的加载动画上）。
- cinema_poster.dart：列表一行 CinemaPosterRow、看过的横向海报条里的一张 CinemaHistoryCard（海报底边是进度，下面片名一行、集数与⋯一行，heightOf 按字号量出整条的高）与海报 CinemaPoster（经百宝箱的小网络图，只认公网 https，按先后取、取不到换下一张）；formatCinemaDuration。
- cinema_episodes.dart：一条线路的选集 CinemaEpisodeGrid（选集页与播放页共用，[人工决策] 在文件头）：一格同宽（按这一段最长的集名量、放得下几列排几列），超过 cinemaEpisodePage 集分段、只建当前一段，打开与选中那集变了时翻到它所在的一段，可倒序。

# 关键规则

- 第三方：片名、播放页地址直接发给规则包里的站点与云解析，各在第一次使用前征得同意，新加的源或换了主机的要重新同意；只搜同意过的源。经境外转发的源在同意弹窗写明，改走转发算换了收件人、要重新同意；转发的白名单跟着规则包改（先改白名单再签规则包，见 server/README.md）。
- 播放：控件全部自己画（mpv 的 Video 用 NoVideoControls，系统播放器只画 VideoPlayer 画面），加载动画只有一份；内核按 cinema_engine.dart（安卓默认系统播放器）；libmpv 的同步 FFI 调用跑在界面线程上，解码线程卡住会连带界面无响应；不要改用 mediacodec_embed 这类直出 Surface 的输出（11-19 模拟器上解码器等不到消费者，返回时卡死），用 media_kit 默认配置。
- 不自动重试（跨模块不变量 9）；超时与上限都在 cinema_http.dart。
- 规则包与时长券都不写进灰度配置：旧版本解析灰度配置是严格的，多一个字段整份拒收。
- 保留：看过的最多 50 条、180 天；播放记录每个源一行、30 天；云解析结果只在内存 3 分钟；选集只在内存 10 分钟、64 部（搜索自带的跟着搜索结果，一次搜索最多 carriedEpisodeLimit 集）；最近的搜索结果只在内存 1 分钟、64 份、估算 4MB；看过的片在各源的编号每部最多 32 个、跟着看过的记录删；本机代理的清单 5 分钟、16 份，探测结论 30 分钟（没定论 1 分钟）、64 条；规则包只留一份；手机不存片名目录（在中转上，保留见 server/README.md）；源的连续失败与暂停只在内存。
- 片名目录型的源：片名只发给中转（请求体里，中转不落库、不写日志），源只收到编号；隐私政策第六节写明（修订 12）。
