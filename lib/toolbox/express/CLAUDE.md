# express 快递（拼多多身份码与快递查询）

定位：百宝箱里的一个工具，对接拼多多官方账号，查询驿站待取件、管理取件手机号（查看、绑定、解绑）、生成取件身份码。账号是拼多多账号，与教务、学习通都无关。协议按授权账号的互操作场景用 Dart 独立重写（来自一次性移交的逆向 SDK，不原样引入），不生成也不绕过拼多多的反爬与风控字段。框架契约（注册表、服务、清除数据）见上一级 lib/toolbox/CLAUDE.md。

- [人工决策] 新增本模块与功能范围、绑定手机号扩成真正的绑定、为让绑定可用用隐藏 WebView 现取 anti_content（原「不生成反爬字段」让步）、不加截屏保护、全屏出示等，标记位于 toolbox_catalog.dart（登记处）、express_models.dart（anti_content 决定与常量）、express_page.dart（扫码范围、绑定手机号管理、首页同学习通写法、账号卡写昵称与取件号、待取件按尾号分组、先读后开、扫驿站码取站点码、只能微信取件与去微信）、express_controller.dart（首次查驿站补关联）、express_login_webview.dart（登录先校验）、express_anti_content.dart（anti_content 实现）、express_identity_view.dart（截屏保护、全屏出示、默认盖遮罩）、express_page.dart 的 _openIdentity（快捷入口直达全屏身份码）。

# 文件职责

- 协议与数据：
  - express_models.dart：会话 PddSession（登录态等同账号，请求头带 AccessToken 或 Cookie 二者其一；nickname 与 pickupMobile 是账号卡用来认出账号的拼多多昵称与常用取件号（打码），pickupMore 表示还绑了别的号，null 表示还没读过、空串表示读过但没给）、常量与 entry_source 枚举 PddConstants（含绑定用 protocol_code/scene/mobile_type/entry_source）、身份码 IdentityCodeResult（expireMills 是剩余有效期）、已绑定手机号 PddBoundMobile（commonlyUsed 是拼多多标的常用号）、绑定预检查 PddBindPreCheck（canFastBind 表示有可免短信快速绑定的已有号；本账号手机号同官方绑定弹窗读 mobile_des，身份码接口的 mobile_info_desc 是另一段说明文字）、驿站待取件 StationPackagesResult（字段按官方 mdkd 包裹页的渲染取：combine_list 按驿站分组成 StationPackageGroup，组内包裹先读 combine_track_list、没有再读 list（审阅移交包说 App 版是 list，两边都无真实样本），包裹 StationPackage 的取件码去掉「取件码」前缀，送货上门只记件数；无待取件时的手机尾号服务端只给前几个、largerThan2 表示还有；带驿站码查时有站名 station_name；only_wx_scan 为真表示账号只能微信扫码取件）、近一周已取出 StationOutPackage（package_out_list：取件地址、取件时间文字、快递公司与运单号）、查物流参数 ExpressTrackQuery（待取件与已取出的件都先取 jump_url 里的、没有再用条目字段，带 order_sn 的是驿站里的件）与物流详情 ShippingTrack（快递公司、运单号、预计送达说明、轨迹 info 与 time，ownerTail 是从 package_info「尾号5678 的快递」取出的寄到手机尾号；不读派件员姓名电话）、扫到的驿站码 parseStationScan（链接、App 内链、JSON、裸码取 station_code，带 t 参数为动态码）与微信取件链接 weChatStationUrl、失败分类 ExpressFailure（verifyRequired 是拼多多风控要先过官方安全验证，带回 verifyToken 与要打开的 verifyPage）。另有短信登录常量 loginAppId/loginEnhanceType/loginPlatformOther（本应用报「其他」平台 4）等与登录时要验证跳去的官方验证页地址（[人工决策] 在文件内，见登录常量）。
  - express_http.dart：请求封装，显式超时管整个请求、响应上限 1MB、日志只记路径；无状态（会话靠 PddSession 请求头带）。errorBody=true 时 4xx 也照常交回响应体与响应头（登录接口的失败原因、验证令牌在 4xx 的 JSON，会话经 Set-Cookie 下发）。改版时最先坏在 expressJson。
  - express_client.dart：短信登录（发验证码 sigerus/mobile/code/request、登录 sigerus/login_mobile、过验证后 sigerus/verify/login；用空会话建客户端，失败原因/验证令牌在响应体即便 4xx，登录成功从 Set-Cookie 拼会话——每次记一行形状帮诊断拼多多认不认空的行为字段）、查手机号列表、本账号昵称（同官方 mdkd 的 nickname/query，scene=dsd.usercenter）、驿站待取件、生成身份码、查实时物流（同官方物流页按参数选接口、只读：带 order_sn 的 POST 驿站物流 dsd/trackbox/shipping/track，其余 GET 通用物流 shipping/track、entry_source=9；两个都不带 anti-content）、关联驿站包裹（bind/mobile/station/package，空 body、带 anti-content 头），以及绑定取件手机号（预检查、快速绑定、发短信验证码、校验、完成绑定（可带备注 alias）、解绑、修改备注）。登录回 54002/54001 归 verifyRequired 带官方安全验证页、54015 归 verifyRequired 带本人验证页（都验完跳回登录页）。统一抛 ExpressFailure；无 error_code 或 error_code 为 null 的成功（如预检查、物流）也算成功；失败文案认 error_msg 与 error_message（物流接口用后者）；40001 及文案点出登录失效的归未登录（说的是验证码的文案不算）；54001 归 verifyRequired、带回 verify_auth_token（令牌不进日志），用户过了官方验证后之后的请求带 VerifyAuthToken 头；其余服务器错误记一行错误码（不记文案）。驿站查询扫码进来时带 station_code，动态码带 dynamic_qrcode=true（同官方）。绑定类接口（除只读预检查）都带 anti-content 请求头，解绑另在 body 的 anti_content 再带一份；解绑 body 字段名是 mobile（值 mobileId）加 box_popup_service/mobile_id_scene；修改备注 POST apoc/express/mobile/alias，body 是 mobile_id、alias、anti_content 与 mobile_id_scene（同官方 6245 的修改备注弹窗）；快速绑定 entry_source="4"、新绑定 "APP"（逆向结论）。
  - express_anti_content.dart：登录与绑定/解绑（含修改备注、关联驿站包裹）要用的 anti_content（v2）生成端口 PddAntiContent 与隐藏 WebView 实现 WebViewAntiContent（同一时刻只生成一个，并发的请求排队取）：首次用到时加载官方 mdkd 页，注入官方 chunk 跑拼多多反爬 SDK 产出 anti_content，轮询取回；主框架只许停在这个官方页（隐藏页没登录态，会自己跳去 login.html 再试图拉起拼多多 App，跳走就丢了生成器，10-22 真机查明后拦下）；有时效、每次现生成不缓存。由 ExpressService 注入、页面把其 webViewController 离屏挂成 1px WebViewWidget（挂上才稳当跑指纹）；测试注入假实现、不起真实 WebView。
  - express_cookies.dart：清掉 WebView 残留拼多多 Cookie 的共用助手 clearExpressWebCookies（无平台或失败只记日志不阻断）；登录前、退出登录、清除数据都调它（见下「关键规则」）。
- 本机数据与服务：
  - express_vault.dart：登录会话的系统安全存储（命名空间 superxd_pdd，deleteAll 只清这个命名空间），另存「已绑号的驿站包裹已关联」标记与每件待取件寄到的手机尾号（只留当前还在待取的件，都随会话一起清），测试用内存版。新增命名空间已加进两份备份排除规则，test/legal_page_test.dart 守护。
  - express_service.dart：服务 ExpressService（实现 ToolboxService）：只持有会话安全存储、建客户端的工厂与 anti_content 生成器（生产 WebViewAntiContent、测试注入假的），存驿站码进相册的一次性导出、临时目录、拉起微信（url_launcher）与官方验证页构造器 verifyPage(Uri)（生产是 ExpressVerifyWebView、测试注入不起 WebView 的假页），都可注入；无业务库（身份码不落盘、快递即查即用）。清除数据删 superxd_pdd 命名空间的会话，并清 WebView 残留 Cookie。serviceId（express）就是工具 id，也是同意记录键。
- 状态与界面：
  - express_controller.dart：页面状态，会话恢复、短信登录（sendLoginSms/loginWithSms/verifiedLogin：用空会话调客户端，成功走 onLoggedIn，失败抛给登录表单；每次现取 anti_content）、驿站查询与身份码生成/到期刷新；登录后、以及恢复的会话还没读过时，在后台并发读昵称与已绑号列表写进会话存回（不挡页面；退出登录与登录失效都先清内存里的会话再删存储，补读据此不把会话写回），读到已绑号列表（打开管理弹层、绑定解绑后重读）时顺手更新取件号；查驿站后按件补查一次物流取寄到的手机尾号（驿站查询不给，ownerOf 给页面分组；查到就存本机、同一件只查一次，普通查询后删掉已不在待取件里的；5 件一批并发，查不到（含查成功但没给尾号）归尾号未知、不存、下次查驿站再查，不挡查询，碰到 54001 这一轮停止补查不弹验证，[人工决策] 在 _fillOwners）；用户点的操作碰到 54001 时记下令牌，页面 takeVerifyToken 取走打开官方验证页，通过后 acceptVerify 让客户端之后带上令牌；一次只跑一个查询（running 记是哪个操作，按钮据此原地转圈；到期刷新另记 refreshing）。打开取件手机号管理前 loadMobiles 并发读好预检查与列表（占 running，按钮原地转圈）。另有一组绑定方法（重读列表、快速绑定、发/校验短信验证码、完成绑定、解绑、修改备注），不占页面 busy（弹层自管进行中），任何一个拿到未登录都清会话回登录态并通知（弹层随之关闭）；除只读的预检查/列表外，每个绑定请求前经 _anti 向 ExpressService.antiContent 现取一个 anti_content；查物流（loadTrack 与补查尾号）不带（[人工决策] 在 express_models.dart）。绑定成功后紧接着关联驿站包裹（同官方）；本账号第一次查驿站时若还没关联过先补一次（[人工决策] 在 queryStationPackages）。关联失败只记日志、不打断绑定或查询，下次查询再补。扫驿站码查过后记住站点码（stationCode），身份码同官方带上它，普通「驿站快递」查询后清空；refreshPackages 是下拉刷新，重做上一次的驿站查询（扫过码的重查同一站点），running 记为 refresh、不让任何按钮转圈；每次查驿站更新「只能微信取件」（onlyWxScan）。verifySession 给登录页用：只读预检查明确回未登录才返回 false。loadTrack 查一件包裹的物流（占 running，trackingKey 记是哪一件，只有那一行的按钮转圈）。
  - express_verify_webview.dart：拼多多官方验证页 ExpressVerifyWebView（查询回 54001 开在 mdkd 之上、登录回 54002/54015 开在登录页之上）：加载调用方给的、已带好令牌与 from 的验证页，由用户本人完成，页面跳回 from 就算通过、返回 true；只许拼多多域名、拦外部 scheme，不读页面内容（[人工决策] 在 express_page.dart 的 _verifyIfAsked）。手指落在网页上时拖动全归网页（EagerGestureRecognizer，登录页同样）：不然 iOS 页面任意位置右滑返回会抢走滑块验证码的横向拖动（10-28 iPhone 截图），在网页上不能右滑返回、顶栏上照常。
  - express_login_form.dart：短信登录表单 ExpressLoginForm（首页登录视图里的主入口）：输手机号与短信验证码，经控制器直连 sigerus 登录；首次发码前经注入的 consent 取同意，发码成功后按钮倒数「重新发送」（60 秒，Timer.periodic），拼多多要求验证时经注入的 verify 打开官方验证页、本人过了再用令牌完成登录；发码/登录失败原地写明、展开淡入（回的不是 JSON 时提示改用网页登录）；输入框是胶囊（同搜索框，占位文字不用浮动标签，聚焦时描边渐变成主色、底色微亮，点 +86 也聚焦），「获取验证码」在验证码框里右侧、倒数时数字滚动，大字号窄屏放不下按钮加六位验证码时按钮挪到框下面（[人工决策] 在 build）；减少动画时直接换；发码、登录一开始就判忙（等同意弹窗也算），连点不会弹两次同意、发两次码。登录前要勾选拼多多自己的「服务协议与隐私政策」（同官方默认不勾、点登录时检查，点「同意拼多多」几个字也能勾，链接经 openTerms 用系统浏览器打开 terms_list.html，[人工决策] 在协议行）。行为字段（fingerprint、touchevent）不伪造、发空值（[人工决策] 在 express_models.dart 的登录常量）。
  - express_login_webview.dart：拼多多官方 H5 登录页 WebView，是短信登录表单之外的后备入口（express_login_form.dart）：登录后经原生 CookieManager 读 HttpOnly 的 PDDAccessToken 组装会话；只许拼多多域名、拦外部 scheme。打开登录页前先 clearExpressWebCookies 清残留 Cookie 再加载，否则会被一加载就读到作废旧 Cookie、直接判「已登录」关页返回。拿到凭据先经 verify 确认会话可用才关页，被判未登录的凭据不再重复确认、等新的（[人工决策] 在 _checkSession）。
  - express_mobile_sheet.dart：取件手机号管理弹层（showExpressMobileSheet，数据由页面先读好传入，弹层里没有加载态）：列已绑号（行内⋯里修改备注与解绑，解绑带确认）、有可快速绑定的已有号时给「绑定本账号手机号」、短信验证绑定其他手机号（输号发码→输码完成，_BindMobileDialog 两步，第一步可顺手填备注）。备注同官方最多 5 个字（拼音没选字时不截）、可清空、有爱人爸爸妈妈三个快捷选项（_AliasField），修改备注弹窗预填当前备注、没改就不发请求（[人工决策] 在 _more）。绑定/解绑逐步由用户点击确认，成功后保留现有列表原地换新、高度平滑过渡，失败走提示条，未登录由控制器带回登录页并关闭本弹层。

# 关键规则

- 登录：主入口是应用内短信登录表单（手机号 + 短信验证码直连 sigerus，号码与验证码只发给拼多多、不保存），官方网页登录留作后备。[人工决策-2026-10-30 21:41:32]（在 express_models.dart 的登录常量）用户选「原生表单直连接口」，推翻 10-19 起「不做 sigerus 短信登录」、把 10-20 的 anti_content 让步扩到登录：发码/登录的 anti_content 仍由隐藏页官方 JS 现生成，行为字段（fingerprint/touchevent）不伪造、发空值（platform 如实报「其他」），拼多多要求验证时仍打开官方验证页由本人完成。同意版本随之升到 pdd-2。10-30 在模拟器上用授权账号实测登录成功（见下「真机已验」），只验过一个账号、一次，风控策略随时可能变，故仍保留网页登录后备。
- 凭据：拼多多登录会话（AccessToken 与账号 Cookie）等同账号登录态，只进系统安全存储（superxd_pdd），业务库与日志都不存；清除数据或退出登录立即删除。短信登录成功时会话从拼多多下发的 Set-Cookie 里取。账号卡的昵称与常用取件号（打码）随会话存在同一处、同删，隐私政策第五节与附录三写明。WebView 的 Cookie 另存一份、也是会话凭据：登录前、退出登录、清除数据都经 clearExpressWebCookies 清掉，残留旧 Cookie 既是凭据滞留、也会让重新登录空跑。
- 多端登录：拼多多同一账号不支持多端同时在线，本模块登录会把其他设备挤下线；同意弹窗与登录落地页都提醒，并引导小号登录后绑大号手机号。
- 绑定取件手机号：绑定/解绑是账号状态变更，必须逐步由用户点击确认（输号→发码→输码→绑定；解绑先确认），不后台自动做。绑定/解绑接口（francis 短信、apoc 绑定、lobit 解绑）都经风控：缺 anti_content 会 403/参数错，故每次请求现取 anti_content 带上（见 express_anti_content.dart）。短信登录见上面「登录」一条。
- 关联驿站包裹：官方在绑定成功后紧接着调 bind/mobile/station/package，把这个号绑定前就到站的件关联进本账号，不调就永远查不到这些件。1.0.0-alpha.6 漏了这一步，靠「首次查驿站补一次」补救（见 express_controller.dart 的人工决策）；以后新增任何绑定入口都要接上它。
- anti_content 合规：逆向确认 anti_content 只能在 WebView 里由拼多多自己的反爬 JS 生成，纯 Dart 生成不了。[人工决策-2026-10-20 17:22:42] 用户选「原生绑定 + 隐藏 WebView 取 anti_content」：用官方 JS 产出合法 anti_content、不自行重写风控，仅用于本人已授权账号的取件手机号绑定/解绑。这是对原「不生成也不绕过反爬字段」的让步，改动要先看 express_models.dart 的标记并与用户确认。查物流 10-30 起同官方带过（18:03:16 与 18:43:18），[人工决策-2026-10-31 13:01:46] 撤回：真机上不带也查得到，带着只让补查尾号多依赖隐藏网页；查物流与驿站、身份码等查询都不带。
- 只能微信取件（only_wx_scan）：拼多多的账号级实验组，官方此时整页只提示用微信扫码。不绕过（换 UA、设备、入口都无效），只做降级提示；第三方 App 让微信打开指定网页要接微信开放平台 SDK 并登记 AppID，不做，所以只拉起微信首页、驿站码靠存相册。
- 已知、暂不改：隐藏 anti_content WebView 是挂在内容区左上角的 1px 定位子项，真机上看得见一个小点。当初怕改绘制（透明度、移出可视区、被遮挡）让页面重置；10-22 真机查明生成器丢失的主因是隐藏页自己跳去登录页（已拦），改绘制是否还会重置没验过，要有授权账号在设备上走一次绑定或解绑验证才改（2026-10-22 用户选定先不动）。

- 身份码是取件凭证、短时有效：不落盘、不打印、界面提示勿分享；本轮不做截屏/录屏保护。
- 第三方来源：拼多多是单独一个来源，首次使用单独征得同意（expressConsentVersion），说明有实质变化就加一档；同意记录按工具 id 记，清除数据时框架撤销。
